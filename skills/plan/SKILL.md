## 流程

1. **通读需求，先确认**：目标、范围、验收标准三件套。信息不足先问，不编造。
2. **拆任务**：每个任务 5-10 分钟内可完成，符合：
   - **精确**：写明操作的文件路径、要跑的命令、预期输出
   - **可独立验证**：做完能判断对错（测试/命令/肉眼可查）
   - **无占位符**：不允许"根据上下文补充""等待后续决定"——每步自己就能产出
3. **排依赖**：明确先后顺序；前一步产出是后一步输入的，标注出来。
4. **执行纪律**：
   - 一步一验证，验证过再进下一步
   - 小步频繁提交（每个逻辑完成点一次 commit），不攒大改
   - 遇到与计划不符的实际情况，停下更新计划，不硬闯
5. **收尾**：逐项对照验收标准；列出未完成项和原因，不隐藏。

**质量原则**：DRY（不复制代码）、YAGNI（不加不必要功能）、TDD（先测试后实现）、频繁提交。

## 反合理化

| 借口 | 现实 |
|------|------|
| "这个步骤很简单，不用写验证" | 没验证 = 无法判断成功，这步不合格 |
| "等实现时再决定" | 计划里的占位符 = 把决策推给未来的自己，重新踩坑 |
| "我一次改完再一起测" | 攒大改 = 出错难定位。一步一验 |
| "提交太频繁显得乱" | 小提交是回滚的地图，不是表演 |

## 验证

- [ ] 每个任务含: 路径 / 命令 / 预期输出
- [ ] 无占位符、无"待定"
- [ ] 步骤顺序 = 依赖顺序
- [ ] 有明确验收标准可逐项核对
