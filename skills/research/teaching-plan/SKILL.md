# 教学方案

## 适用
需要把一块知识变成别人能学会的内容: 培训课、教程、讲义、学习路径、上手文档。
不适用: 一次性问答 (直接回答即可)。

## 流程

1. **先写学习目标, 用可观察动词**: "能独立配置 X 并排错" 而不是 "理解 X"。动词只能用: 说出/列出/区分/配置/实现/调试/评估。**写不出的目标说明这块内容还没想清楚。**
2. **测前置**: 明确学这个之前必须会什么。前置缺失是学习失败最常见的原因 (不是内容太难, 是缺前置)。
3. **按"用得上"排序, 不按知识体系排序**。先给最小可用的完整闭环 (哪怕只覆盖 20% 场景), 再补边界与例外。体系化排序适合查阅, 不适合学习。
4. **每个知识点四件套**: 为什么需要它 (痛点) → 它是什么 (一句话定义) → 怎么用 (最小可跑示例) → 什么时候不该用 (反例)。
5. **示例必须可跑**: 给出完整可复制的输入 (代码/命令/数据), 并写出预期输出。示例跑不通的教程等于没有教程。
6. **练习带自检**: 每个练习写清"做对了会看到什么"。学习者能自己判断对错, 才有独立练习的可能。
7. **评估对齐目标**: 每一条学习目标都要有对应的检验方式 (练习/问题/项目)。**没有检验方式的目标要从目标里删掉**, 不要留着凑数。
8. **附常见卡点**: 列出学习者最可能卡住的地方与解法 (环境差异、版本差异、认知误区)。

## 反合理化
- "先把概念讲清楚再动手" → 概念脱离使用场景记不住。先用起来, 再回头补原理。
- "例子简单点就行, 主要讲原理" → 简单例子无法暴露真实难点, 学生一上手就崩。
- "练习让他们自己找题做" → 无自检的练习没人做。
- "知识点尽量全覆盖" → 覆盖不全不致命, 无目标无检验才是。宁可少而可检验。
- "目标写'理解'也行" → 不可观察 = 无法评估 = 无法改进教学。

## 验证
- [ ] 学习目标用可观察动词, 逐条可检验
- [ ] 前置要求已列
- [ ] 顺序按实用性, 首个闭环最小可用
- [ ] 每个知识点四件套齐全
- [ ] 示例可跑且有预期输出
- [ ] 练习带自检判据
- [ ] 每条目标有对应检验方式; 无检验的目标已删除
