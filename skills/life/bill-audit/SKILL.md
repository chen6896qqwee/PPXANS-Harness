# 账单与订阅审计

## 适用
用户给一堆账单截图、CSV、PDF 或订阅列表, 要算总额、找异常、清理订阅。
不适用: 需要代为支付、取消、退订的操作。本技能只出结论与清单, 绝不代扣款或代取消。

## 流程

1. **逐条抄录, 一行一笔**: 商户名 / 金额 / 币种 / 扣费周期 (月付、年付、一次性) / 扣费日。抄录和计算分开做, 先抄完再算。
2. **用 `read_document` 读账单文件**; 图片版对账单用 `ocr_image` 提字。读不出或模糊的条目写 `[未识别]`, 不要跳过后当作不存在。
3. **换算统一口径**: 全部折成同一周期 (建议月), 年付除以 12 并标注"年付折月"。有汇率要求的先问清汇率来源, 问不到就保留原币种分币种汇总, 不要自己编一个汇率。
4. **计算一律走 `code_run`**, 不手算汇总。把金额数组喂进去求和/求平均/算占比, 输出的中间结果要贴出来。
5. **三类异常必查**:
   - 重复扣费: 同商户同金额同周期出现多笔
   - 静默涨价: 同商户历史金额变化
   - 僵尸订阅: 周期为月但近期无任何使用痕迹 (使用痕迹需问用户, 不能凭空判定)
6. **区分事实与建议**: 金额、日期是事实; "这个可以取消"是建议, 必须单独成节并给理由。不要替用户决定取消什么。
7. **输出结构**: 总支出 (月/年) → 明细表 → 异常清单 (带证据行) → 可优化项 (按节省金额排序) → 需用户确认的模糊项。

## 反合理化
- "差不多一个月三百多" → 账单审计的唯一价值就是精确。用 `code_run` 算到分。
- "年付的直接当 12 个月月付就行" → 要标"年付折月", 否则用户会误以为是每月实际扣款额。
- "汇率大概是 7.2" → 编汇率会让总额错得看不出来。问不到就分币种汇总。
- "这笔看不清, 应该是 39" → "应该是"就是错账的源头。标 `[未识别]`, 让用户补。
- "这个订阅用户肯定不用了" → 没有使用数据就不能下这个判断。问, 或者只列出来提示用户自查。
- "我顺手帮他把自动续费关了" → 涉及钱的写操作一律不代做。给步骤, 让用户自己点。

## 验证
- [ ] 每笔都有 商户/金额/币种/周期 四要素, 缺项已标 `[未识别]`
- [ ] 所有汇总由 `code_run` 算出, 中间数组已贴出
- [ ] 年付折月、币种口径已显式标注
- [ ] 三类异常 (重复扣费/涨价/僵尸) 均已检查并写明结论, 无数据处写明"无法判断"
- [ ] 事实与建议分节, 建议均附理由
- [ ] 未执行任何支付、取消、退订类操作
