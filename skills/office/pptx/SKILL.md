# 演示文稿

## 适用
- 用户要一份可放映的 `.pptx`: 汇报、复盘、方案、培训, 内容以文字要点为主。
- 需要读出已有 `.pptx` 的逐页文字, 或检查文件结构是否完好。
- 不适用: 图片/图表/动画/母版定制/演讲者备注/模板套用。这些在 PowerPoint 或 Keynote 里做更快, 本技能只保证"内容与结构正确、文件能开"。

## 核心事实
`.pptx` 也是 ZIP 包: `ppt/presentation.xml` 记录页序, `ppt/slides/slideN.xml` 是每页, 母版与版式在 `ppt/slideMasters`、`ppt/slideLayouts`, 主题在 `ppt/theme`。生成器从零写出完整包 (含母版、空白版式、主题、每页关系文件), 不依赖任何模板。

生成器只有三类页: **封面页**、**章节页**、**内容页** (标题 + 要点 + 子要点 + 页码)。版式由固定坐标控制: 16:9, 边距 0.66 英寸, 标题 30pt 粗体, 正文 18pt, 子要点 16pt, 要点超过 8 条自动降字号并给出过密警告。

## 工具
脚本目录 `scripts/`, 只用 Python 3.9+ 标准库:

| 命令 | 用途 |
|---|---|
| `python scripts/pptx_tool.py create --from-md outline.md --title "封面标题" --subtitle "副标题" --out deck.pptx` | Markdown 大纲 → pptx; 自动追加封面页 |
| `python scripts/pptx_tool.py read deck.pptx [--labels]` | 逐页提取文本; `--labels` 标注形状名 (Title/Body) |
| `python scripts/pptx_tool.py validate deck.pptx` | ZIP/XML/母版-版式-页关系/空页/形状计数 |

大纲语法:
- 第一个 `#` = 封面标题 (或用 `--title` 覆盖), 后续 `#` = 章节页;
- `##` = 内容页标题;
- `-` = 一级要点, 缩进两个空格 = 二级要点;
- 内容页标题下没有要点时会给出一页"(本页无正文)"占位, 提示你补内容。

## 流程

1. **先定叙事结构, 再写大纲**。每页只讲一个判断; 页标题写成结论句 (「三条主线均按期交付」), 不要写主题词 (「交付情况」)。封面 → 结论 → 论据 → 风险/下一步 → 附录。
2. **控制单页信息量**: 一级要点 ≤ 6 条, 每条 ≤ 30 字; 超了拆页, 不要靠缩字号硬塞。生成器在要点超过 8 条时会警告。
3. **写 Markdown 大纲**, 用 `#`/`##`/`-` 三级结构, 不写配色与坐标 —— 生成器统一处理版式, 混写样式只会让结果不可预测。
4. **生成**到目标路径, 文件名用主题 + 日期, 不用"最终版/v3"。
5. **回读校验**: `read` 逐页检查标题、要点顺序、错别字; 页数与大纲预期一致。
6. **结构校验**: `validate` 必须 `ok: true`; `slide_text_chars` 中不应出现 0 (空白页)。
7. **视觉核对**: 本机有 PowerPoint/LibreOffice 时打开或转 PDF 看一遍重点页 (封面 + 最密的一页); 没有就明确说明"已做结构与内容校验, 未做视觉排版核对"。
8. **交付说明**: 文件路径、页数、每页主题一句话、未覆盖能力 (图片/图表/动画/备注)。

## 边界与限制
- **只生成, 不改已有演示文稿**。需要改模板或改别人的 ppt, 用 PowerPoint 本身; 手工拆 XML 极易破坏关系文件。
- **不含图片、图表、表格、图标、动画、切换、演讲者备注、母版自定义**。
- **字体**: 主题用 Calibri (西文) + 微软雅黑 (中文)。目标机器缺字体时 PowerPoint 会自动替换, 行宽可能变化; 交付时若在意一致性, 请告知用户。
- **不保证不溢出**: 生成器按字数估算框高并启用自动缩放 (`normAutofit`), 但极端长句仍可能在真实渲染里换行过多。项目流程要求回读并把每个要点控制在 30 字内。
- `.ppt` (二进制老格式) 不支持; 先另存为 `.pptx`。

## 反合理化
- "先把字都塞进一页, 讲的时候再展开" → 观众看的是幻灯片, 不是你的讲稿。一页一个判断。
- "标题写'情况说明'就行" → 主题词不传递结论, 观众要自己推理。标题直接写结论。
- "配色我自己调一下" → 生成器的版式是一个整体, 只调一处会造成对比度与对齐问题。要换风格就改生成器, 不要手改单页。
- "read 出来没问题就能交付" → read 只证明文字在, 不证明版式没问题。视觉核对要么做, 要么在交付时明说没做。
- "少两页没关系" → 页数与大纲不一致通常意味着某段大纲没被解析 (缩进/空行)。先查大纲, 再交付。

## 验证
- [ ] 大纲结构完整: 封面标题、每页标题、要点层级
- [ ] `create` 输出的 `slides` 与大纲预期页数一致, `warnings` 为空
- [ ] `read` 逐页核对标题与要点, 无错别字、无乱序
- [ ] `validate` 返回 `ok: true`, 无 `slide_text_chars` 为 0 的页
- [ ] 若本机可渲染, 已看过封面页与最密一页; 否则已在回复中说明未做视觉核对
- [ ] 回复中写明路径、页数与未覆盖能力
