# 表格工作簿

## 适用
需要产出可被他人继续使用的表格文件 (xlsx/csv)。
不适用: 纯分析结论 (那用 data/metric-analysis)。

## 流程

1. **先定用途**: 这份表是给人读 (汇报)、给人录 (采集)、给程序读 (导入) 还是给公式算 (模型)。四种用途的字段设计完全不同 —— 给人读要少而精, 给程序读要规范且无合并单元格。
2. **设计字段表 (先写再建)**: 字段名 / 类型 / 单位 / 是否必填 / 取值示例 / 口径说明。字段名用中文短名 + 无空格, 避免前端与公式兼容问题。
3. **一个表只放一个粒度**。明细与汇总是两张表, 不要混在同一张里 (混了就再也无法透视)。
4. **口径单独一页/一节**: 每个指标的定义、计算式、时间范围、数据源。这是表格能被信任的唯一凭据。
5. **公式优于硬编码**: 用公式表达派生列, 便于源头更新后整表联动。硬编码的数字要标注快照时间。
6. **图表只在能回答问题时加**: 趋势用折线、构成用堆叠、对比用条形。不要为了好看加图表。
7. **交付前自检** (逐条跑): 表头无重复无空 / 无整列空值 (允许的例外要标) / 数字列不含文本 / 日期列格式统一 / 合计行与明细一致 (抽样复算) / 无隐藏的合并单元格。
8. **落盘**: 明确写出文件路径与每张表的粒度, 便于对方核对。

## 反合理化
- "先建表再想字段" → 表建好了再改字段, 所有公式与图表都要重做。
- "合并单元格好看" → 合并会破坏排序、筛选、透视与程序读取。用重复值或分组列代替。
- "数量对得上就行, 口径不用写" → 没有口径的表三个月后没人敢用。
- "合计行我大概加一下" → 合计必须能被明细复算出来。抽样验算是硬要求。

## 验证
- [ ] 用途已确认, 字段表先于文件存在
- [ ] 单表单一粒度, 明细与汇总分离
- [ ] 口径说明完整 (定义/公式/时间范围/来源)
- [ ] 派生列用公式而非硬编码
- [ ] 通过交付前 6 项自检, 合计已抽样复算
- [ ] 文件路径与表结构已在回复中说明
