# 中文正式文档

## 适用
需要交付给他人的正式中文书面材料: 方案、研报、汇报、总结、说明、通报。
不适用: 聊天式回复、内部随手笔记。

## 流程

1. **先确认三件事**, 缺一件就问: 给谁看 (决策者/执行者/外部)、要什么结论 (批准/知情/执行)、篇幅约束。写错受众是所有返工的根源。
2. **搭骨架 (层级不超过三级)**:
   - 一级: 一、二、三 (或 1. 2. 3. 按文档惯例)
   - 二级: (一)(二)(三) 或 1.1 1.2
   - 三级: 仅在确有必要时使用; 超过三级说明该拆成附件
3. **开篇给结论**: 正式中文文档不是倒金字塔小说。第一段写"本报告要说明什么、结论是什么", 后面才是论证。决策者只读第一段就能做判断。
4. **一段一义**: 每段只承担一个论点, 首句是论点句。禁止把两个不相干的结论塞进同一段。
5. **用语纪律**:
   - 用「应当/需/建议」区分强制、必要、可选三档, 不要全用「应该」
   - 数字带口径与时间 (「截至 X 月, 口径为 Y」)
   - 不用形容词做结论 (「效果良好」→「完成率 92%, 超目标 2 个百分点」)
   - 首次出现的缩写给全称
6. **风险与不确定单列一节**。正式文档隐瞒不确定性, 后面会以更大代价暴露。
7. **结尾给下一步**: 需要谁做什么、什么时候、需要什么授权。
8. **落盘用 write_file** 写成 Markdown 或按用户要求的格式; 需要 .docx/.pptx 时明确说明产出格式。

## 反合理化
- "先把内容写满再整理结构" → 无结构的长文本几乎无法整理, 只能重写。
- "领导喜欢看详细过程" → 多数决策者先看结论与风险。过程放附件。
- "这段数据不太确定, 先不写来源" → 不写来源等于把风险转嫁给读者。标不确定度。
- "用语口语一点更亲切" → 正式文档的亲切感来自清晰, 不是来自口语化。

## 验证
- [ ] 受众/结论/篇幅三要素已确认
- [ ] 首段含结论
- [ ] 层级 ≤ 3 级且编号体系统一
- [ ] 每段一段一义, 首句为论点
- [ ] 数字带口径与时间, 无形容词式结论
- [ ] 有独立的风险/不确定节
- [ ] 结尾有明确的下一步与授权需求
