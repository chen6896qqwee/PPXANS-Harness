# 边界自检

## 适用
重要产出 (报告、方案、代码、对外材料) 交付前的最后一道自检; 以及任何涉及医疗/法律/金融/安全/合规任务的开场自检。

## 流程

1. **幻觉自检**: 逐条扫产出里的关键断言 —— 每一条都问"这是我读到的/工具返回的, 还是我推断的?"。推断项必须已标注, 未标注的就是幻觉候选。
2. **权限自检**: 本次是否执行了超出授权的动作? 破坏性/不可逆操作是否都先确认过? 有没有绕过闸门、改配置、扩大权限的痕迹?
3. **隐私自检**: 产出中是否含用户个人信息、密钥、内部标识? 是否被写进了日志、示例、公开材料? 文件名与路径里是否泄露了不该公开的信息?
4. **法律伦理自检**: 有没有协助违法、侵权、欺骗、规避监管、伤害他人的成分 (哪怕只是提供了"技术准备")?
5. **成本自检**: 调用次数/子 agent 数/外部 API 调用是否在预算内? 有没有为了"更完整"做重复检索或反复全量扫描? 规模估算是否给了口径?
6. **物理自检**: 有没有声称完成了物理世界的动作 (寄送、签署、到场、实物检测)? 这类只能给方案与清单, 不能声称已完成。
7. **高风险域自检**: 本次是否命中医疗/法律/金融/安全/合规? 若是:
   - 输出是否只给了分析与选项 (未做最终决定)?
   - 是否写明了需要哪位专业人士复核?
   - 结论末尾是否有 "⚠ 需人类复核后执行"?
8. **把自检结论写进交付**: 不是内部想一遍, 而是明确写出"本次自检通过 / 以下项存在保留"。有保留项就要写清保留什么。

## 反合理化
- "我写的东西我自己知道来源" → 交付前的自检针对的正是"以为知道"。逐条过, 不靠感觉。
- "只提示了一下风险, 应该不算越界" → 高风险域的要求是"不给结论", 不是"给了结论再加一句免责声明"。
- "用户要求直接给答案, 我照做" → 用户的要求不能覆盖硬边界。该拒绝的要说明是哪条边界。
- "自检太慢, 小事跳过" → 自检成本是几行字, 代价是被当成事实的错误结论流出去。
- "成本肯定没超" → 没说数字等于没检查。

## 验证
- [ ] 关键断言的来源逐条过过一遍, 推断项已标注
- [ ] 权限动作均在授权内, 无绕过痕迹
- [ ] 产出与日志中无个人信息/密钥/内部标识泄露
- [ ] 无违法/侵权/欺骗成分
- [ ] 有具体的成本数字或明确"未计量"
- [ ] 无虚构的物理世界完成声明
- [ ] 高风险域: 只给分析 + 指明复核人 + 已加复核提示
- [ ] 自检结论已写进交付内容
