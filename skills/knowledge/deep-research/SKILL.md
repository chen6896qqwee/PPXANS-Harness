# 深度调研

## 适用
需要跨多个来源才能回答的问题: 技术选型、市场信息、竞品对比、事实核查、政策解读。
不适用: 单点事实 (直接查一次即可)、用户已知答案只是要你复述。

## 流程

1. **先写问题, 再开检索**。把模糊需求压成 2~4 个可判真假的具体子问题。写不出子问题说明需求还没澄清, 先回去问清楚 (用 clarify), 不要用"多搜几个关键词"代替思考。
2. **每个子问题先定来源类型**: 一手 (官方文档/原文/法规/官网)、二手 (媒体/博客/教程)、推测 (论坛/评论)。检索时优先一手。
3. **检索用 web_search, 抓正文用 fetch_page**。搜索页只给线索, 结论必须落到正文; 只看摘要就下结论是最常见的错误来源。
4. **记录来源台账**: 每条关键结论旁边写下来源 URL + 发布时间。时间敏感的内容 (价格/政策/版本) 必须标时间。
5. **主动找反例**。对每个主要结论补一次"它可能错在哪"的检索。找不到反面材料也要在结论里写"未找到反面证据"而不是默认它为真。
6. **冲突不调和, 陈列分歧**。两个来源冲突时, 说明各自立场与时间, 让用户判断, 不要选一个顺眼的当真相。
7. **输出结构**: 结论 (3~5 条, 带来源) → 分歧与不确定 → 待用户决定的问题 → 附: 来源清单。

## 反合理化
- "搜到第一页就够了" → 第一页多数是二手转述。至少回到一手原文确认一次。
- "这个数字看起来合理" → 合理不是来源。没有来源的数字不许写进结论。
- "时间不够, 先给个大概" → 给大概可以, 但必须标"未核实", 不能伪装成已核实。
- "只有这一个来源, 那就算确认了" → 单一来源 = 待验证, 明说。

## 验证
- [ ] 每个子问题都有明确答案或明确的"查不到"
- [ ] 每条关键结论附来源 URL (+ 时间, 如时间敏感)
- [ ] 至少做过一次反证检索 (并说明结果)
- [ ] 冲突项被单列, 没有被静默调和
- [ ] 未核实的部分被显式标注
