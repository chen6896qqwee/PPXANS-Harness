# 来源核验

## 适用
用户给出一个说法、截图、链接、数字, 要求判断真伪或可信度。也用于给自己刚写出的结论做交付前自检。

## 流程

1. **把说法拆成最小可验证单元**。一句话里常混了 3 个断言, 只有一个假。逐条列出: A 为真、B 为真、C 未知。
2. **给每个单元定来源等级**:
   - L1 一手: 官方发布、原始文件、法规原文、当事人声明、可复现的实测
   - L2 权威二手: 有署名与编辑责任的媒体报道、行业报告
   - L3 弱二手: 博客、教程、聚合站 (常互相抄)
   - L4 无来源: 截图、转述、"网上说"、AI 生成文本
3. **查一次原始出处**。L3/L4 必须回溯到 L1 或明确标注"无法回溯"。回不去的, 结论只能到"未证实"。
4. **找时间线**。很多"假消息"其实是过期真消息。标出该说法的原始时间, 与当前状况对比。
5. **区分四种终态**: 已证实 (有 L1) / 部分证实 (拆出的断言真假混合) / 未证实 (查不到, 但没被推翻) / 已推翻 (有 L1 反证)。
6. **写结论时把等级带上**。格式: 断言 → 等级 → 依据。不写"应该是真的"这种无信息量的话。

## 反合理化
- "大家都这么说" → 传播广泛度与真实性无关, 这正是需要核验的信号。
- "符合我的判断" → 符合预期是最危险的确认偏差。特意找一个不信它的来源看看。
- "太麻烦了, 干脆说无法判断" → 无法判断也是结论, 但必须说清"查了什么、卡在哪", 而不是省事。
- "AI 说的应该没问题" → AI 生成文本是 L4, 与截图同档。

## 验证
- [ ] 说法被拆成可独立验证的单元
- [ ] 每个单元标了来源等级
- [ ] L3/L4 做过向 L1 的回溯尝试 (并记录结果)
- [ ] 明确了时间线
- [ ] 终态用了四档之一, 没含糊
