# 任务拆解

## 适用
目标明确但路径不清, 或路径很长需要分段推进。任何"要做一件复杂的事"的第一动作。

## 流程

1. **先定终态**: 用一句话写清"做完了长什么样", 必须是可判断真假 (有具体产出/可被检验), 不能是"优化一下/推进一下"。
2. **倒推里程碑**: 从终态往回推 —— 要得到它, 上一步必须产出什么? 推到当前状态为止。倒推比正推少走弯路。
3. **切成步骤, 每步满足三条**:
   - 单一产出物 (具体到文件/数据/决策)
   - 可独立验证 (有客观判据, 不靠"感觉差不多了")
   - 单一责任 (谁做, 或哪个角色做)
   不满足就继续切。
4. **标依赖**: 每步写 `依赖: [步骤号]`。没有依赖的步骤就是可以并行的 —— 显式列出来, 别让串行习惯浪费并行度。
5. **标不确定点**: 每步旁边写"该步最可能失败的原因"。失败原因说不出来的步骤, 通常是你还没想清楚。
6. **留回滚**: 不可逆步骤单独标红, 写明回滚方式 (或"不可回滚, 需先备份/先确认")。
7. **输出**: 目标终态 → 步骤表 (序号/产出物/依赖/验证方式/风险) → 可并行组 → 不可逆步骤清单 → 第一步是什么。

## 反合理化
- "先干起来再说" → 没有终态的动手会在中途反复推翻。至少花一轮把终态定下来。
- "步骤越细越好" → 过细会失去验证价值。粒度标准只有一个: 能否独立验证。
- "依赖关系后面再说" → 依赖决定顺序与并行度, 后面补等于重做计划。
- "这步太简单不用列" → 简单但阻塞的步骤最常被漏。列出来成本是一行字。

## 验证
- [ ] 终态可判真假 (有具体产出)
- [ ] 每个步骤有单一产出物与验证方式
- [ ] 依赖关系显式, 可并行组已标出
- [ ] 不可逆步骤已标出并有回滚说明
- [ ] 明确了第一步动作
