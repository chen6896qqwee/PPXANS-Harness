# 多智能体编排

## 适用
任务规模超出单条推理链的容量: 需要并行处理、需要多视角对抗、需要隔离执行, 或需要"实施→审查"分离。
**不适用: 一个 agent 能做完的事。** 多智能体是组织手段, 不是性能魔法 —— 每个子 agent 都有独立的启动、上下文与成本开销; 拆得不好比自己做更慢更贵。

## 流程

1. **先判断该不该拆** (三条任一成立才拆):
   - 可并行: 子任务之间无依赖, 拆分能真正缩短墙钟时间
   - 需隔离: 子任务要用互相冲突的假设/权限/工作目录
   - 需对抗: 需要独立视角审查, 避免同一上下文里的自我确认
   三条都不成立 → 自己做, 别拆。
2. **算并发预算**: 先看可用的子智能体并发上限 (legion_status), 再定派几个。**派的个数不能超过并发上限**, 否则多余的在排队 (白等)。嵌套委派时每一层都要留额度, 别把父层的额度吃光。
3. **选定拓扑** (按依赖形状, 不按喜好):
   - parallel: 相互独立, 各自出结果后汇总 → 适合探索性调研
   - pipeline: 强顺序依赖, 前一环产出即后一环输入 → 适合"拆解→实现→审查"
   - supervisor: 需收敛的决策 → 多专家并行 → 分歧检测 → 评审打回 → 定稿
   - debate: 有争议的判断 → 正反方对抗, 强制把反方论据摆上来
   - review: 实施者 + 只读审查者循环 → 适合质量要求高的产出
4. **每个子 agent 必须拿到三样东西**:
   - 清晰完整的任务描述 (含上下文, 子 agent 看不到你的对话历史)
   - 明确的交付格式与验收标准
   - 差异化视角 (否则同模型同上下文 → 一个错全错)
5. **审查者一律只读**。让审查者能改代码, 它就变成了第二个实施者, 审查意义消失。
6. **设超时与熔断**: 每个子任务要有时限; 审查循环要有最大轮数, 到上限就停放并交回主 agent 裁定, 不要无限重试。
7. **回收子进程**: 任务结束必须回收 (killAgent / shutdownAll)。长跑进程里不回收的子 agent 会线性堆积, 每个都带独立的数据目录与连接。
8. **汇总时不堆砌**: 主 agent 要仲裁整合 (去重、标冲突、给结论), 不是把各方回复拼接后原样返回。
9. **边界**: 高风险领域 (医疗/法律/金融/安全) 的委派, 子 agent 必须只读, 产出只能作为人类决策的输入。

## 反合理化
- "多派几个人总没坏处" → 每个子 agent 都在花你的预算与机器配额。无关角色产生的噪音会稀释结论。
- "大家结果一致说明对" → 同模型同提示的一致是必然的, 不是独立印证。要差异化视角才有对抗价值。
- "让审查者顺手把问题改了更快" → 审查者一改, 实施者学不到东西, 且破坏了"谁改谁负责"的追溯链。
- "超时了再等等就好" → 卡死的子 agent 在占用并发额度, 会让其他任务排队。超时即断。
- "子任务不用写验收标准, 它们自己会判断" → 子 agent 看不到全局, 没有验收标准就会各自发挥。

- [ ] 拓扑与依赖形状匹配
- [ ] 每个子任务有独立视角与验收标准
- [ ] 审查者只读
- [ ] 有超时与熔断上限
- [ ] 子进程已回收
- [ ] 结果是仲裁整合的, 不是拼接的
