# 语音转写与纪要

## 适用
输入是音频文件 (wav/mp3/m4a), 需要文字、纪要或字幕。
不适用: 实时通话、需要声纹识别锁定身份的场景 (手里的工具没有说话人分离能力)。

## 流程

1. **先确认前置条件, 再动手**: `voice_transcribe` 需要 `config.voice.asr` 配好 (base_url + api_key, OpenAI 兼容 /audio/transcriptions)。没配就明确告诉用户"转写不可用, 需要先配 ASR", 不要试一次拿到报错后含糊带过。
2. **`vad_detect` 只吃 16-bit PCM WAV**。其他格式先说明需要转码, 不要直接喂进去然后报错当失败。用 VAD 找出真正有人说话的区段, 便于判断有效时长和是否有静音空洞。
3. **`vad_detect` 探区段 → `voice_transcribe` 转写**, 顺序不能反。先探后转能提前发现"这段其实是空的", 省一次 API 调用。
4. **不确定的词必须标 `[待确认]`**: 人名、公司名、型号、数字、专有名词最容易错。给最可能的写法并标存疑, 不要选一个读起来顺的就当定论。
5. **数字与时间二次核对**: 金额、日期、版本号、倍数。听不清就标出来, 这类错在纪要里后果最重。
6. **区分"原文"与"整理"**: 逐字转写是一层, 归纳纪要是另一层。纪要不能篡改原话含义, 关键结论要能回溯到原句。
7. **不做说话人分离的假象**: 工具没有 diarization。如果用户需要"谁说", 明确说做不到, 除非音频里本身有自报身份或称呼。
8. **输出结构**: 音频基本信息 (时长/格式/有效语音占比) → 逐字稿 (标 `[待确认]` 与静音位置) → 纪要 (结论/待办/数字) → 存疑清单。

## 反合理化
- "听不清但意思明显是这个" → 意思明显是推断, 逐字稿里只能留 `[待确认]`。
- "格式不对, 我猜转码能行" → 先说要转码, 不要用一次报错去试。
- "说话人我大概能听出来是谁" → 工具没有声纹能力, 写出来就是把猜测当事实。
- "纪要嘛, 意思对就行" → 金额和日期错一位, 纪要就是负资产。逐字符核对。
- "这段空白我跳过不说" → 静音空洞影响"有效信息量"的判断, 要写出来。
- "ASR 没配, 那我凭大概印象总结" → 没有转写就不存在纪要。明说不可用。

## 验证
- [ ] ASR 配置状态已确认, 不可用时已明说而非含糊处理
- [ ] 音频格式已确认是否 16-bit PCM WAV, 非 WAV 已提示转码
- [ ] 先过 `vad_detect` 再过 `voice_transcribe`
- [ ] 专有名词/数字不确定处已标 `[待确认]`
- [ ] 逐字稿与纪要分开, 纪要结论可回溯原句
- [ ] 未虚构说话人身份
- [ ] 输出含有效语音占比与存疑清单
