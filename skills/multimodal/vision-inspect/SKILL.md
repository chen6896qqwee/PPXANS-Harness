# 视觉信息提取

## 适用
输入是图像 (截图、照片、扫描件、视频帧), 需要提取其中的信息用于后续任务。

## 流程

1. **先说清图的类型与用途**: 截图 (界面/报错/聊天)、照片 (实物/场景)、扫描件 (文档/表格)。类型决定提取重点。
2. **三层提取, 逐层分开**:
   - 可见文字: 逐字抄录 (人名、数字、代码、报错原文) —— 这是最可靠的一层
   - 可见结构: 界面元素、表格行列、版式关系
   - 推断内容: 因果、意图、情绪、未显示的部分 —— **必须显式标为推断**
3. **数字与代码逐字符核对**。OCR 最易错的是 0/O、1/l、5/S、小数点与负号。涉及金额、版本号、坐标时二次确认, 拿不准就标"[待确认]"而不是猜一个合理的。
4. **不确定处明说**: 模糊、遮挡、分辨率不足的部分写"无法辨认", 不要用上下文补全成看似合理的内容 —— 这属于幻觉。
5. **不描述画面外的东西**: 只讲图里有的。图外推断 (时间、地点、人物身份) 单独一节标为"推测"。
6. **处理敏感信息**: 图中出现的身份证号、手机号、地址、密钥等在输出中打码, 除非用户明确要求原文。
7. **输出**: 图类型 → 文字转录 (原样) → 结构说明 → 推断 (标注) → 无法辨认项 → 敏感信息提示。

## 反合理化
- "这里看不清但应该是 1000" → "应该是"就是幻觉的入口。标待确认。
- "从上下文能推出这个时间" → 推断放推断节, 不能混进转录。
- "反正用户要的是内容, 格式不重要" → 结构信息 (哪个字段对应哪个值) 常比文字本身更重要。
- "截图里的手机号直接抄进去" → 输出会进日志与记忆。默认打码。
- "视频我抽一帧看看就够" → 单帧可能错过关键变化。涉及过程的任务要多帧对比。

## 验证
- [ ] 图类型与用途已说明
- [ ] 文字转录与推断严格分开
- [ ] 数字/代码逐字符核对, 存疑处标 [待确认]
- [ ] 无法辨认部分已明说
- [ ] 无画面外内容被当作可见事实
- [ ] 敏感信息已打码
