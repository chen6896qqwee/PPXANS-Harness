# 扫描件与截图取字

## 适用
输入是扫描件、拍摄的纸张、界面截图, 需要把里面的文字或表格变成可用的结构化文本。
与 `vision-inspect` 的分工: 那个负责"看懂图", 这个负责"精确取字并核对"。

## 流程

1. **先看版式再取字**: 用 `read_image` 判断图属于单据 / 表格 / 正文段落 / 界面截图。版式决定提取顺序和是否需要保表格结构。
2. **精确取字用 `ocr_image`**。它需要系统装 tesseract (含中文包) 或配 `config.ocr` 云 key; 缺任一条件都要明说"OCR 不可用", 不要退化成"我看着图猜"然后当原文给出。
3. **数字逐字符核对**: OCR 的高危混淆对是 0/O、1/l/I、5/S、8/B、`.` 与 `,`、负号与破折号。金额、单号、日期、型号必须二次核对, 拿不准标 `[待确认]`。
4. **表格保留行列关系**: 输出用结构化格式 (markdown 表或 CSV), 合并单元格用重复值或 `↑` 标注。不要为了好看把结构摊平, 结构本身就是信息。
5. **区分可见与推断**: 图里印着什么就是什么。看不清的写 `[无法辨认]`, 不要用"这种单据一般写的是"来补。
6. **敏感信息打码**: 身份证号、手机号、银行卡、地址在输出里默认打码 (保留可核对的头尾), 除非用户明确要求原文。
7. **需要落盘时用 `write_file`** 存成 .md 或 .csv, 并在回复里说明存到哪。
8. **输出结构**: 图类型与版式 → 文字/表格转录 → 存疑与无法辨认项 → 敏感信息提示。

## 反合理化
- "tesseract 没装, 我直接看图说" → 看图能理解大意, 但单据的数字要的是精确。明说 OCR 不可用的代价。
- "这个金额印得有点糊, 应该是 1,280.00" → "应该"不能进转录结果。标 `[待确认]` 并给出候选。
- "表格摊平成一行也能用" → 行列关系丢了, 下游没法处理。保留结构。
- "身份证号反正是用户自己的" → 输出会进日志和记忆。默认打码。
- "OCR 出来了就直接贴, 不用再看一眼" → OCR 原文不等于原文。数字行必须复核。
- "看不清的地方留空就行" → 留空和"图上没有"无法区分。写 `[无法辨认]`。

## 验证
- [ ] 图类型与版式已判断
- [ ] OCR 可用性已确认 (tesseract 或云 key), 不可用已明说
- [ ] 数字/单号/日期已逐字符复核, 存疑标 `[待确认]` 并给候选
- [ ] 表格保持了行列结构, 合并单元格已标注
- [ ] 无"看不清但推断补全"的内容
- [ ] 敏感信息已打码
- [ ] 落盘文件路径已告知 (若落盘)
