# debug — 根因排障

## 流程

1. **读完整报错**：全文读，包括栈与 code（`ERR_*`），别只看第一行。
2. **稳定复现**：写出最小复现命令。不能复现就先想办法复现，别改代码。
3. **二分定位**：把链路切成两半，确认问题在哪半，重复到最小单元。
4. **根因陈述**：用一句话说清"为什么"，并指出它在哪一行。
5. **先写回归**：修之前先加一个能失败的测试，再改到它通过。
6. **验证修复**：跑全量回归，确认没有连带破坏。

## 反合理化

- "先改改看"——猜测式修改会把真正的根因埋得更深。
- "这个报错以前见过"——相似报错≠同一根因。
- "加了 try/catch 就不报错了"——那是掩盖，不是修复。
- "改完好了就行"——没写回归，下次还会犯。

## 验证

必须提供：① 最小复现命令与原始报错；② 定位到的 `文件:行号` 根因；③ 新增的回归测试；④ 全量回归结果。
