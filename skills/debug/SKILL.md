## 流程

1. **复现**：拿到稳定触发问题的最小步骤。不能稳定复现的 bug 无法验证修复。
2. **隔离**：用二分法缩小范围（注释一半代码 / 关掉一半条件 / 对比最小样例），找到"能复现"与"不能复现"的边界。
3. **定位**：在边界处看真实状态（打印日志/断点/检查输入输出），找到**根本原因**，而不是表面症状。确认根因后再动手，不猜。
4. **修复**：只改根因处。**每次只改一个变量**，改完立刻重跑复现步骤。
5. **验证**：
   - 原问题不再出现
   - 写一条能捕获此 bug 的测试（防止回归）
   - 确认没有破坏相邻功能

**检查顺序**（低成本→高成本）：输入数据 → 参数传递 → 状态/缓存 → 环境差异 → 并发/时序。

**调试反模式**：改一行→跑→没反应→再改一行→再跑…… 这叫乱试，不是调试。每次改动前先说出你的假设和预测，预测对了才说明真懂了。

## 反合理化

| 借口 | 现实 |
|------|------|
| "这个 bug 很诡异，再重启试试" | 重启只是延迟复现，没有根因分析 |
| "我猜是这里的问题，改一下" | 猜测 = 没有定位。先隔离再改 |
| "修好了"（但没跑验证） | 没验证的"修好"是自欺 |
| "加个 try-catch 吞掉错误" | 吞错误 = 把 bug 埋得更深 |

## 验证

- [ ] 能稳定复现原问题
- [ ] 已定位到根因（能说清为什么出错）
- [ ] 修复后原问题消失，且附有测试证据
- [ ] 已补一条防回归测试
