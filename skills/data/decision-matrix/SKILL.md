# 决策矩阵

## 适用
有 2~6 个明确候选方案, 需要给出有依据的推荐 (而不是凭直觉挑一个)。
不适用: 候选方案还没成形 (先做拆解)、标准本身有争议 (先对齐标准)。

## 流程

1. **先定标准, 再接触方案**。顺序反过来必被"某个方案的亮点"带偏 —— 先看方案会不自觉地为它造标准。
2. **标准分类**: 必须满足 (硬门槛) / 越优越好 (打分项) / 越低越好 (成本项)。硬门槛不满足的方案直接淘汰, 不进打分。
3. **定权重并说明理由**。权重来源要写清 (谁的要求、什么约束)。权重加起来是 100, 不允许"都重要"。
4. **逐项打分, 附依据**。每一格写分数 + 一行依据。没依据的格子打"?"而不是给个中间分 —— 虚假的精确比留白更危险。
5. **汇总与排序**: 加权总分 + 排名。同时列出"如果权重改为 X, 排名是否翻转"。
6. **敏感性检验 (必做)**: 挑权重争议最大的两个标准, 各上下调 20%, 看结论是否还成立。结论易翻转 → 说明这是权重之争而非方案之争, 要把权重问题交回用户。
7. **输出**: 标准与权重表 → 打分矩阵 → 推荐 + 理由 → 敏感性结论 → 什么信息能让结论更确定。

## 反合理化
- "先看看方案再说标准" → 这就是确认偏差的入口。标准必须独立于方案产生。
- "这个方案明显最好, 不用打分" → 明显最好通常意味着标准被单一维度主导。打分正是用来暴露这一点。
- "打个中性分吧, 信息不足" → 中性分会被当成真实评价参与汇总。信息不足应标 "?" 并在结论里说明。
- "权重差不多就行" → 权重是决策的真身。权重随便定 = 结论随便定。
- "加权总分第一就选它" → 先看敏感性。翻转的结论不能当成推荐。

## 验证
- [ ] 标准先于方案确定, 且分了硬门槛/打分项/成本项
- [ ] 权重有理由且合计 100
- [ ] 每个分数都有依据 (无依据标 "?" 而非中间分)
- [ ] 做了权重敏感性检验并报告是否翻转
- [ ] 推荐结论与矩阵一致, 没有额外夹带偏好
