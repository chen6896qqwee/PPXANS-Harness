# 指标分析

## 适用
某个指标出现变化或异常, 需要给出"是什么原因"的结论。
不适用: 纯取数 (直接查即可)、预测未来走势 (那是预测, 需另立前提与置信区间)。

## 流程

1. **第一步永远是核对口径, 不是找原因**。指标定义改了吗? 分母变了吗? 数据延迟了吗? 采集时段对得上吗? 口径变化导致的"变化"占了实际异常的一大半。
2. **确认变化是真实的**: 用第二来源/同期另一维度交叉验证。只有一条链路算出来的数字, 可能是巧合或 bug。
3. **拆解结构**: 总量 = 各维度之和。按维度逐层拆 (地区/渠道/品类/版本/新老用户), 找出贡献最大的那一两个分支。定位到分支后再看趋势, 而不是在总量上继续猜。
4. **区分四种成因**:
   - 真实业务变化 (需求/竞争/季节)
   - 数据结构变化 (用户构成、渠道结构变了)
   - 口径/采集变化 (定义、埋点、延迟)
   - 巧合/统计波动 (小样本尤其常见)
5. **给出替代解释并排除**: 至少列 2 个其他可能原因, 逐条说明为什么不是 (或"无法排除")。
6. **结论带置信度**: 高 (多源印证 + 机制清楚) / 中 (结构拆解一致但机制不明) / 低 (只有相关性)。**相关不等于因果** —— 没有机制解释时只能说到"相关"。
7. **输出**: 口径核对 → 变化真实性 → 拆解定位 → 成因判断 + 置信度 → 被排除的替代解释 → 需要什么数据才能升档。

## 反合理化
- "先赶紧看看哪个维度降了" → 口径没核实就拆解, 很可能在解释一个不存在的变化。
- "这条曲线和那个事件时间吻合, 就是它导致的" → 时间吻合是最弱的相关性证据。找机制, 或者降低置信度。
- "小样本也能算出比例" → 分母 < 30 的比例波动几乎全是噪声, 必须标出来。
- "只给一个原因显得专业" → 只给一个原因且排除了其他, 才是专业。只给一个原因是漏掉了排除步骤。

## 验证
- [ ] 口径已核对 (定义/分母/延迟/时段)
- [ ] 变化经第二来源交叉验证
- [ ] 做了维度拆解并定位到主要贡献分支
- [ ] 列出并排除了替代解释
- [ ] 结论带置信度档位
- [ ] 未把相关性表述为因果
