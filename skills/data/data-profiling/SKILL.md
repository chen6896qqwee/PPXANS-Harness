# 数据剖析

## 适用
第一次拿到一份数据集 (CSV/Excel/JSON/SQL 结果), 在任何分析之前。
不适用: 已经熟知的、稳定的数据源 (直接分析)。

## 流程

1. **先看形状, 不看内容**: 行数、列数、每列类型。行数极少 (< 30) 或列数极多 (宽表) 时先说明局限, 别急着算指标。
2. **逐列体检**, 每列记录:
   - 类型与单位 (数字列里混文本是最常见的坑)
   - 缺失率; 缺失率 > 20% 的列单独列出
   - 取值范围与明显越界 (负数金额、未来日期、身高 300cm)
   - 唯一值数量 (唯一值 = 行数 说明是 ID; 唯一值 = 1 说明是常量列)
3. **查重复**: 全列重复 (真重复行) 与关键列重复 (同一实体多条记录) 要分开说, 后者往往代表粒度问题。
4. **确认粒度**: 一行代表什么? (一次交易/一个用户/一天) 说不清粒度, 后面所有汇总都可能是错的。
5. **找口径文档**: 字段定义、时间范围、来源、更新频率。找不到就明确写"口径未知", 并列出因此不能做的分析。
6. **看分布不看均值**: 均值会被极值带偏。至少看中位数与四分位, 标出异常值占比。
7. **输出体检报告**: 形状 → 粒度 → 逐列问题清单 → 口径状态 → **可用性结论** (能做什么分析、不能做什么)。

## 反合理化
- "数据挺规整的, 直接开算" → 规整的假象来自只看前几行。缺失与异常常在尾部。
- "缺失的填个 0 就行" → 填 0 会把缺失变成真实的零, 直接污染所有均值与汇总。
- "异常值删掉就好" → 先判断是录入错误还是真实极值。删掉真实极值会低估风险。
- "不用知道粒度也能算总和" → 粒度错了, 总和就是把同一件事算了两遍或漏算。

## 验证
- [ ] 给出了行数/列数/类型
- [ ] 逐列体检结果 (缺失率/范围/唯一值) 完整
- [ ] 区分了真重复行与同实体重复记录
- [ ] 明确了数据粒度
- [ ] 口径来源已确认或明确标为未知
- [ ] 给出了"能做/不能做"的可用性结论
