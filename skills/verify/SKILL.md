# verify — 完成前核验

## 流程

1. **列出断言**：把"已完成"拆成可判定的原子断言（例：内核能启动 / 测试 0 失败 / 接口返回 200）。
2. **为每条断言指定证据命令**：必须是别人能照抄复现的命令，不是"我看过了"。
3. **真跑**：执行命令，原样记录输出（含失败）。
4. **对账**：断言 → 证据 → 通过/不通过。任何一条没证据，就标"未验证"。
5. **失败即停**：不通过就修，修完重跑全套，不挑着跑。

## 反合理化

- "应该没问题"——"应该"不是证据。
- "这个改动很小"——小改动照样要跑回归。
- "本地测过了"——本地过了但没跑全量，等于没测。
- "日志里没报错"——没报错 ≠ 跑通了，可能是分支没进。

## 验证

收尾必须提供：① 断言清单；② 每条对应的命令与原始输出；③ 明确的通过/不通过结论。禁止只报"已完成"。
