## 流程

**铁律: 在拿出证据之前, 不要声称任何东西已成功。验证优先, 声称其次。**

1. **声明前自问**：我声称完成的这件事，怎么证明它真的完成了？
2. **选择验证方式**（按可信度排序）：
   - 自动化测试（单元/集成测试跑过且通过）
   - 实际执行命令/接口，看到预期输出
   - 读取产物内容，逐项核对需求
3. **跑验证**，把**证据**（命令 + 输出/测试结果）留档。
4. **对照验收标准**逐项核对：每一项标 ✓（有证据）或 ✗（未验证），不混合。
5. **无法验证的，如实说"未验证"**，不要用推测顶替。

**验证优先于代码**：复杂改动先写测试（RED→GREEN→REFACTOR），测试是行为契约，也是完成判据。

## 反合理化

| 借口 | 现实 |
|------|------|
| "我手动试过没问题" | 手动测试结果没留档 = 没证据。贴出命令和输出 |
| "代码看起来是对的" | 看起来对 ≠ 跑起来对。运行它 |
| "我先说完成，用户发现问题再修" | 未验证的"完成"是在移交债务 |
| "这个改不了/环境不允许验证" | 那就明确说"未验证+原因"，不包装成"已完成" |
| "测试太麻烦，功能这么简单" | 简单功能的验证更简单，不是不做 |

## 验证

- [ ] 每个"已完成"项都有可复现的证据（测试通过/命令输出/产物内容）
- [ ] 验收标准逐项核对，未验证项单独列出
- [ ] 无"应该没问题"式的推断性声明
