# 系统 / Agent 有机体操作系统 — RC1 规范手册

> 版本：RC1（Release Candidate 1）　|　状态：草案评审　|　目标平台：桌面皮皮虾（ppx-agent）
> 模板：把 Agent 运行时抽象为一个有机体：静态八大系统（结构） + 动态行为层（单次会话 Runtime 链路） + 生殖与发育系统（生命周期与进化）。
> 配套实现映射见 `docs/ARCHITECTURE.md`（皮皮虾现有模块落地情况）。

---

## 0. 设计哲学

一个成熟 Agent 不是把"模型 + 工具"拼起来就行，它应该像生物体一样：

- **有结构**——分工明确又协同的系统（静态八大系统）。
- **有行为**——单次任务里一套自洽的循环驱动各部门协作（动态行为层）。
- **会成长**——有诞生、分化、自我修复、进化（生殖与发育系统）。

三大支柱共同构成 **Agent 有机体操作系统**。本文档为 RC1 版规范，定义系统边界、运行时驱动链路、生命周期规则与接口契约；横切流程（如 RAG）单独裁决归属，不强行塞进任何一个格子。

## 1. 静态结构：八大系统

| 系统 | 隐喻 | 职责 | 边界（管什么） |
|------|------|------|----------------|
| ① 神经系 | 认知 | 推理、决策、规划、反思 | 记忆侧仅负责**检索触发、查询生成、相关性评估、推理采信、候选记忆写入**。生成/压缩/淘汰/归档/删除及生命周期规则定义权归⑤。核心：LLM + 模型适配层 |
| ② 循环系 | 数据总线 | 整个 Runtime 的数据总线：Context、State、Event、Command、Result、Memory Update | 所有系统间数据交换必经它。承担 Runtime Contract、工作流编排、组件调度启停、任务状态追踪、重试与断点恢复、定时任务、后台清理执行（RC1 扩充） |
| ③ 呼吸系 | 环境感知 | 与外部世界的信息交换：用户输入、文件、图片、音视频、浏览器、MCP、API、系统通知 | 所有任务从这里开始。它是唯一与外部世界接触的入口 |
| ④ 消化系 | 信息编绎 | 把原始数据变成认知系统可理解的知识表示：OCR、ASR、解析、Chunking、实体抽取、去噪、信息融合、结构化 | 只管"原始→知识表示"这一转换。转换后的产物交给①或② |
| ⑤ 排泄系 | 遗忘-归档 | Runtime 的代谢，边界**仅限跨会话长期记忆**：记忆压缩、冷热层、历史会话归档、冗余识别、过期治理、遗忘与删除候选生成 | OCR/浏览器等功能性缓存、任务状态、运行日志归各功能系统自管，清理由②执行、⑧授权（RC1 附件A §3.2 收窄）。不是删除——会记住，也必须会遗忘 |
| ⑥ 运动系 | 工具执行 | 把决策真正执行出去：MCP、Function Calling、API、Browser、Python、Shell、文件操作、软件控制 | 只管"执行"，不管"决定要不要执行"（那是①）与"能不能执行"（那是⑧） |
| ⑦ 内分泌系 | 目标-调节 | 持续调节行为模式：长期目标、人格、用户偏好、风险偏好、成本预算、Reward、主动程度、优先级 | **不直接执行任务**，持续影响认知系统的倾向与权重 |
| ⑧ 免疫系 | 安全治理 | 权限校验、内容安全、风险控制、沙箱、日志审计、异常恢复、越权检测、数据隔离、资产删除授权（预授权策略清理 + 单次独立审批双模式）、许可证与合规检查（RC1 补充） | **任何动作都必须经过它**。它是执行前的闸门与执行后的审计 |

### 一 组关键约束
- **③ 是唯一对外入口**：一切外部信号必须经呼吸系进来，禁止各系统私自接触外部世界。
- **① 只做认知，不做执行**：它产出"决策意图"，经⑧校验后交给⑥执行。
- **⑦ 不直接干活**：它只调激素（权重/倾向），真正动手的还是①。
- **⑧ 必须在场**：任何动作——执行、读写、删除——先过免疫闸门。
- **② 是唯一总线**：系统间不走私有通道，全部走②的事件/命令/结果。

## 2. 动态行为层：单次会话的 Runtime 动态链路

静态系统是"器官"，那一次对话/任务是如何驱动它们协作的？这是本条要回答的——**感知 → 认知 → 决策 → 执行 → 反馈** 的闭环如何在运行时流通。

### 2.1 五段式主循环

```
  外部信号
     │
     ▼
┌────────────────────────────────────────────────────────────┐
│ ③ 呼吸系（感知）                                          │
│   接收原始输入：用户 text / 文件 / 图片 / 浏览器 / 系统事件 │
│   打包成统一 Inbound Event，推给②                          │
└────────────────────────────────────────────────────────────┘
     │ Inbound Event
     ▼
┌────────────────────────────────────────────────────────────┐
│ ④ 消化系（认知前处理）                                    │
│   把原始 Input 转成知识表示：OCR / 解析 / Chunking / 结构化 │
│   产出 "Input Knowledge"（结构化上下文）                   │
└────────────────────────────────────────────────────────────┘
     │ Input Knowledge
     ▼
┌────────────────────────────────────────────────────────────┐
│ ① 神经系（认知）                                          │
│   1. 意图理解 / 查询生成                                    │
│   2. 检索触发：向⑤要"该记着什么"（⑤供长期记忆的检索结果）  │
│   3. 推理 / 规划 / 决策                                    │
│   4. 反思：对比目标与⑦注入的偏好，把倾向调入 context        │
│   产出 "Decision Intent"（决策意图，含候选动作序列）        │
└────────────────────────────────────────────────────────────┘
     │ Decision Intent
     ▼
┌────────────────────────────────────────────────────────────┐
│ ⑧ 免疫系（执行前闸门）                                    │
│   权限校验 / 风险控制 / 内容安全 / 沙箱判定 / 越权检测      │
│   放行 or 拒绝 or 升级审批                                  │
│   产出 "Authorized Command"（已授权命令）                  │
└────────────────────────────────────────────────────────────┘
     │ Authorized Command
     ▼
┌────────────────────────────────────────────────────────────┐
│ ⑥ 运动系（执行）                                          │
│   执行 MCP / API / Shell / 文件 / 浏览器                   │
│   产出 "Tool Result"（原始执行结果）                       │
└────────────────────────────────────────────────────────────┘
     │ Tool Result
     ▼
┌────────────────────────────────────────────────────────────┐
│ ④ 消化系（执行结果编译）                                  │
│   把原始 Tool Result 去噪 / 结构化 / 融合                  │
│   产出 "Compiled Result"                                   │
└────────────────────────────────────────────────────────────┘
     │ Compiled Result
     ▼
┌────────────────────────────────────────────────────────────┐
│ ① 神经系（反思 / 反馈集成）— 也是下一轮循环的起点          │
│   评估结果是否达成目标：成功→收束；失败/不一致→再走一轮     │
│   同时把结果写入记忆候选，交给⑤                            │
└────────────────────────────────────────────────────────────┘
     │ 记忆候选 + Reward 信号
     ▼
┌────────────────────────────────────────────────────────────┐
│ ⑤ 排泄系（记忆写入 / 遗忘治理）                           │
│   决定哪些进长期记忆、压缩哪些、淘汰哪些                    │
│   [合并] ⑦ 内分泌系（Reward 反馈）                        │
│   本轮成败 → 更新行为倾向 / 长期目标的权重                 │
└────────────────────────────────────────────────────────────┘
     │ 回到① → 循环下一轮（直到目标达成或明确收束）
```

### 2.2 循环驱动规则
1. **一步一轮**：主循环以"一次感知→一次反馈"为最小单位；复杂任务拆成多轮，每轮独立走完整链路。
2. **全部走②**：链路里每一段之间的交接（Inbound Event、Input Knowledge、Decision Intent、Authorized Command、Tool Result、Compiled Result、记忆候选、Reward）都是②总线上的消息，**没有旁路直通**。
3. **⑧可能出现两次**：主干上至少一次（执行前闸门）。若①在规划阶段就触发了外部资源访问（如检索外部库、写文件），那一步的访问同样过⑧。
4. **重试与断点在②**：某段失败（如网络异常、工具超时）→② 按策略重试或挂起断点，恢复后从断点续跑，不重头再来（状态在②全程可追踪）。
5. **⑦持续在场**：认知阶段①读⑦注入的上下文（目标/偏好/风险/优先级）；反馈阶段⑦收 Reward 修正权重。⑦不做主循环节点，但贯穿始终。
6. **每小时量级后台代谢**：⑤的冷热层迁移、归档、冗余清理、②的定时任务——由②的调度器按周期触发，走同一链路（感知=定时器到点，执行=自行治理），不占用户交互主循环。

### 2.3 主循环与静态系统的一一对应
| 主循环阶段 | 主导系统 | 协作系统 |
|-----------|---------|---------|
| 感知 | ③呼吸系 | ②（打包/转发） |
| 认知前处理 | ④消化系 | ② |
| 认知 | ①神经系 | ⑤（检索）、⑦（倾向注入）、② |
| 决策闸门 | ⑧免疫系 | ② |
| 执行 | ⑥运动系 | ②、⑧（审计日志） |
| 结果编译 | ④消化系 | ② |
| 反思/反馈 | ①神经系 | ② |
| 记忆写入/遗忘 | ⑤排泄系 | ①（候选）、② |
| Reward 调节 | ⑦内分泌系 | ①、② |

## 3. 生殖与发育系统：生长、分化、自我修复 △RC1 新增

静态八大系统描述的是"现在的、成熟形态的、单个实例"。生物体的另一半——**从诞生到成熟、复制分化、在损伤中自愈、随时间进化**——对应到 Agent 就是生命周期与进化。这属于第 0 条哲学里"会成长"那根支柱，单列一条。

### 3.1 隐喻 → Agent 对应

| 生物隐喻 | Agent 对应 | 说明 |
|---------|-----------|------|
| 生长 | 自我进化（能力/记忆/技能累积） | 一次任务沉淀一种经验、一个技能、一条用户偏好，Agent 越来越强 |
| 分化 | 能力扩展 + 子实例分化 | 长出新工具/新技能（能力扩展）；必要时派生子 Agent 承担专门角色（分化：军团/子进程/专门化 Specialist） |
| 自我修复 | 自愈 + 断点恢复 | 崩溃自愈、损坏数据修复、残留清理、异常恢复（融合⑧免疫系与②调度） |
| 繁殖 | 实例复制 / 配置迁移 | 同一份"基因"（核心价值 + 人格 + 经验库）可复制到新实例，继承记忆与能力 |

### 3.2 生命周期状态机（RC1 定义）

```
   ╔════════════╗   首次有实质对话   ╔════════════╗
   ║  born 诞生 ║ ─────────────────▶║ growing生长║
   ╚════════════╝                   ╚════════════╝
        ▲                                  │ 经验/技能/记忆累积达标
        │ 实例新生（复制基因）               ▼
        │                            ╔════════════╗
        │                            ║  mature成熟 ║
        │                            ╚════════════╝
        │                                  │
        │ 拆分/失活/归档                    ├──▶ evolving 进化（重大能力跃迁，如：新增固定 skill / 生成稳定画像 / 微调）
        └──────────────────────────────────┘
                                           ├──▶ reproducing 繁殖（分化派生，产生新的 born 子实例）
                                           └──▶ archived 归档（生命周期终结：能力稳定→归档为只读经验，供母体/新实例继承）
```

- **born**：新实例诞生（或从母体复制基因而来）。仅有核心价值 + 人格，无个人经验。
- **growing**：通过一次一次主循环累积经验、技能、画像；记忆层⑤持续写入。
- **mature**：经验/技能/画像稳定，进入高效稳定期；大部分能力进入"半自动"（少盯多验）。
- **evolving**：重大能力跃迁（新增固定技能、生成稳定用户画像、提取可为全局复用的经验）。可周期性发生。
- **reproducing**：分化派生——产生专注于特定任务/角色/人的子实例（对应军团/多 Agent Specialist）。
- **archived**：生命周期终结。不是删除——降级为只读经验库，供母体或其他实例继承（呼应⑤"不是删除"）。

### 3.3 进化载体（RC1）
| 载体 | 归属系统 | 说明 |
|------|---------|------|
| 经验库（成功轨迹 / 失败轨迹） | ①→⑤ | 一次主循环的成败沉淀为可复用经验 |
| Skill（能力扩展） | ①↔⑥ | 把实践验证过的方法固化成可调用技能，属"分化/生长" |
| 用户画像 / Agent 人格 | ⑦ 内分泌系 | 长期偏好的正规存储，持续调节行为 |
| 自愈引擎 | ⑧ + ② | 损坏修复、崩溃恢复、残留清理，是"自我修复"的载体 |
| 模型微调 / 适配层 | ① 神经系 | 可选高阶：把积累的（query, 理想回复）对沉淀成微调/适配数据。RC1 版列为**可选能力**，不强制任何实例必须微调 |

### 3.4 生殖与发育系统与静态系统的关系
- 它是**跨系统能力的编排**，不是第十个独立器官：生长主要靠①+⑤+⑦，分化靠①+⑥（+军团编排），自愈靠⑧+②，繁殖靠②（配置/记忆复制）。
- 生命周期状态存储在②总线（State），由①在关键节点触发迁移判断，迁移动作交②调度执行。
- 与静态八大系统并列，构成"第八+九条"完整有机体描述：**八系统为存量器官（怎么运作），生殖/发育系统为存量演化（怎么生长/再生/繁殖）**。

## 4. 横切流程裁决

某些能力横向穿过多个系统，不整体归属某一格。裁决原则：**按职责切分，各归其位，不为一并新增模块。**

### 4.1 RAG（检索增强生成）示例
| RAG 环节 | 归属 | 理由 |
|---------|------|------|
| 检索发起（判断需要什么、生成查询、评估相关性、采信检索结果） | ①神经系 | 认知系统决定"要不要、查什么、信不信" |
| 检索取回（对外获取知识） | ③呼吸系 | 从外部（数据库/网页/文件）取回，是对外交换 |
| 检索编译（把取回内容转成认知可用的知识表示） | ④消化系 | 去噪/Chunk/结构化，是"原始→知识"转换 |
| 检索结果写入长期记忆候选 | ①→⑤ | 认知提候选，排泄系做最终写入治理 |

### 4.2 裁决通则
1. **判断归①（认知）**：凡涉及"要不要做、检索什么、信不信、采不采用"的判断侧，一律归认知。
2. **取回归③（呼吸）**：凡涉及"从外部世界拿"的取回侧，归环境感知。
3. **转换归④（消化）**：凡涉及"原始数据→知识表示"的转换侧，归信息编绎。
4. **安全归⑧（免疫）**：任何环节触发的越权/风险/内容安全，统一报⑧裁决。
5. **状态归②（总线）**：横切流程的中间态与断点记录，全部落在总线。

## 5. 接口契约（RC1 定稿）

### 5.1 系统级接口
| 系统 | 对外能力（供谁调用） | 输入 | 输出 |
|------|---------------------|------|------|
| ①神经系 | 认知决策能力（自己+②协调） | Input Knowledge / Compiled Result | Decision Intent / 记忆候选 / Reward 信号 |
| ②循环系 | 总线：事件发布/订阅、命令、状态、调度 | Event / Command / State | 分发结果 / 调度任务 |
| ③呼吸系 | Inbound/Outbound 通道 | 外部原始信号 | Inbound Event；Outbound=对外输出 |
| ④消化系 | 编绎能力 | 原始 Input / Tool Result | 结构化知识表示 |
| ⑤排泄系 | 记忆检索 / 记忆写入 / 遗忘治理 | 查询 / 记忆候选 / 治理指令 | 检索结果 / 写入确认 / 淘汰&归档清单 |
| ⑥运动系 | 工具执行 | Authorized Command | Tool Result |
| ⑦内分泌系 | 行为调节能力 | Reward 信号 / 目标变化 | 倾向/权重上下文 |
| ⑧免疫系 | 安全校验 / 审计 / 授权 | 待执行动作 / 待审计日志 | 放行/拒绝/升级审批 / 审计记录 |

### 5.2 总线消息类型（②）
| 类型 | 语义 | 示例字段 |
|------|------|---------|
| Event | 发生了什么（事实），只读广播 | `{seq, ts, type: inbound|tool_result|memory_update, payload}` |
| Command | 要执行什么（意图），带回路 | `{id, ts, target: ⑥|④|⑤, verb, payload, ack}` |
| Result | 某次命令的结局 | `{cmdId, ts, ok, data, err}` |
| State | 当前运行时状态（可被①/⑦读） | `{sessions, tasks, lifecycle, quota, cost}` |
| Memory Update | 记忆写/归档事件，全系统可见 | `{ts, op: write|compress|archive|forget, scope}` |

### 5.3 免疫双模式授权（⑧）
- **预授权策略清理**：符合白名单策略的批量清理，按配置直接授权放行，记审计日志。
- **单次独立审批**：越出策略的关键操作（删除资产、外部写、高权限调用），必须逐次独立审批，不可累积授权、不可由预授权覆盖。
- 任何③→⑥的对外动作，⑧必然在场；缺失⑧即判定为安全事件。

## 6. 错误与异常恢复（RC1）

| 场景 | 归属 | 处理 |
|------|------|------|
| 网络超时 / 工具失败 | ② | 重试策略或断点挂起，从断点续跑 |
| 权限不足 / 越权 | ⑧ | 拒绝 + 审计；显式记录越权事件 |
| 记忆写入失败 | ⑤ | 重试；候选暂存②，下轮重放 |
| 损坏数据 / 崩溃 | ⑧+②+自愈 | 自愈引擎修复、残留清理（见 ARCHITECTURE.md 自愈基准） |
| LLM 提供不稳定 | ① | 多 provider 回退（皮皮虾已有 _llmWithFallback） |
