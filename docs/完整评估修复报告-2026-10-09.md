### 2.2 处置：按确定性映射表移植

新增移植脚本（参考副本 → src 目标 + 相对 import 重写），一次移植 **14 个文件**：

```
store.js → src/utils/store.js          wal.js → src/utils/wal.js
pii.js → src/utils/pii.js              schema.js → src/utils/schema.js
similarity.js → src/utils/similarity.js  id.js → src/utils/id.js
provenance.js → src/memory/provenance.js
fact-store.js / session.js / l0 / l2 / l3 / experience / memory-ticker → src/memory/
```

**为什么这次移植是安全的**：`store.js` 只 import `node:fs/path/crypto`（零相对路径），且是严格超集（src 无独有导出）；其余文件的相对 import 由脚本按 `utils/` 优先规则重写，移植后 `depcheck` 与 `node --check` 全绿。

**顺带的收获**：`src/utils/store.js` 的新版带来 **F6 同步锁闸门** —— 传 `async` 回调给 `withFileLock` 会当场抛错，而不是"看起来持锁、实际 no-op"。项目注释里写明它**已因此真丢过用户数据**。

## 三、逐项修复清单

### P0 —— 安全相关（新增，此前完全缺失）

**`findInlineExec`：解释器内联执行检测（硬拦截）**

缺陷：首词合法的命令可以携带任意内联源码逃过前缀白名单 —— `node -e "..."` / `python -c "..."` / `bash -c "..."` / `powershell -enc ...` 全是合法首词；`npx <pkg>` 等于即取即执行远程包；`find . -exec cat {} ;` 借 find 执行任意程序；`git -c pager=... log` 借 git 注入配置。

实现要点（**实测 9/9 拦、6/6 放、opt-in 正确**）：

| 必须拦截（allow_all 也拦，`hard=true`） | 必须放行 |
|---|---|
| `node -e "..."` · `python -c "..."` · `bash -c "..."` · `powershell -enc ...` | `node app.js` · `bash build.sh` |
| `npx evil-package` · `find . -exec cat {} ;` · `git -c core.pager=cat log` | `python train.py --epochs 3` · `python -m venv .venv` |
| `env node -e "1"` · `sudo python -c "..."`（包装器不得绕过） | `git log --oneline` · `find . -name "*.js"` |

需显式 `security.allow_inline_exec=true` 才放开。**刻意不误伤** `python -m venv`（模块执行）与脚本文件调用。

**`scanToolResult`：工具结果注入扫描**

缺陷：只扫原始文本。攻击载荷常被 JSON 转义（`\u0068`）或嵌在深层字符串叶子里 —— **原文扫不到，模型解码后就读到了**。实现为「解析 JSON + 所有字符串叶子一并纳入词表」。
