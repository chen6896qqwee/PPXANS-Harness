# 皮皮虾 (PPX Agent) 全面评价 — v1.1.0（第十一轮）

评价方式：本轮基于对源码、测试、脚本与运行实况的系统取证（非纸面推断）。已核对的事实包括：全量测试 452 项 448 过 0 失败 4 网络跳过；`web/` TypeScript 类型检查 0 错误（`tsc --noEmit` exit 0）；实测脚本 acceptance 23/23、bench 0 失败、eval 7/7；src 70 个 .js 文件（约 425KB）；git 历史 v1.0.0→v1.1.0 共 12 轮提交。

## 1. 功能完整性 — 9.3/10

**很强，覆盖一个生产级 agent 的绝大部分能力面：**

| 能力域 | 依据 |
|---|---|
| 对话主链路 | `chat`/`chatStream` + 多 provider 健康探测回退 + 工具循环 + 流式，实测通道认证全部生效 |
| 编排模式 | 7 种 `react/single/plan-exec/router/blackboard/graph/legion`（`src/mode/`） |
| 工具系统（33 项） | 分类齐全：file/net/system/memory/selfmod/misc；含 `run_command`/`read_file`/`write_file`/`http_request`/`ocr_image`/`read_document`/`ingest_document`/`spawn_agent`/`refine`/`refine_skill`/`code_act` 等 |
| 记忆四层 | L0 事件日志 → L1 原子记忆（高斯衰减 + 倒排 + 可选 dense/BM25 RRF + LLM 查询扩展）→ L2 场景 → L3 画像；L1→L0 daily 归属 |
| 会话 | append-only 事件溯源、压缩层、**按天分片**（`default-YYYY-MM-DD.jsonl`）、fork/replay、会话管理/重命名 |
| 多后端 | http（原生 tool_calls）/ openclaw / deepseek（fence 围栏代理）三路回退 |
| 多 agent | legion 多进程军团 + DAG 编排 + `spawn_agent` 差异视角/仲裁/SDD 审查循环 |
| 集成 | 自研零依赖 MCP 客户端（stdio+HTTP 已联调 DeepWiki）、文档加载、OCR（tesseract+云回退）、多模态（视觉 provider 路由） |
| 通道 | HTTP/飞书/企业微信/日志，统一 ChannelManager 注册表 + `ppx-channels` CLI 自助配置/连通测试 |
| ANS | 价值对齐（核心价值注入）/ 主动任务生成（proactive）/ 生命周期（born→…→reproducing） |
| 自愈/安全 | selfheal 启动体检/崩溃恢复；命令守卫三层防线、SSRF、PII 脱敏、symlink 加固、CORS、token 持久化 |

**薄弱环节（真实缺口，非臆测）：**
- **多 agent 编排使用率不足**：按 `ARCHITECTURE.md` 自述，角色分工的 `dispatch` API「保留为军团 API，生产无内置消费方」——有一定面积是「存在但少用」的镀金面。
- **离线兜底窄**：`localIntent` 是**固定规则引擎**（问候/时间/记住/读文件/列目录），不依赖 LLM，但覆盖面窄，属可用而非智能。
- **零依赖的双刃剑**：dense 检索需外部 embedder 才生效、OCR/PDF 依赖外部命令/API——是不引入 npm 依赖的必然代价，属有意的外包边界。

## 2. 响应质量 — 8.5/10

- **上限由所选模型决定**：推理正确性、专业性、意图理解都强依赖 provider。此前云端实测（火山 coding/v3 + deepseek-v4-flash）LLM 直连 6/6、记忆闭环真实生成并持久化；本地 LM Studio qwen 也能跑但质量/速度差一个量级。
- **Agent 自身的"答题之外"能力加分**：记忆提炼（感知既有记忆去重）、查询扩展 + RRF 融合提升召回、场景自动归档、`refine` 把失败轨迹→经验、`refineSkill` 把成功轨迹→可复用 Skill——这些让输出随时间变好，属"自我提升的响应质量"。
- **诚实扣分**：本地默认模型 n_ctx=4096 时，**system prompt 本身（核心价值+persona+记忆+经验+33 个工具描述）已逼近 4k**，长一点就溢出。本轮已加窗口感知预算 + 溢出自动降档，但**对 4k 小窗口，仅靠历史裁剪救不了「system prompt 本身过大」**——真正解法应是按需加载工具描述 / 精简注入。这是当前最实质的响应质量短板。

## 3. 语言一致性 — 9.5/10

- 源码注释、日志、CLI 提示、配置、错误信息**全部中文且术语统一**（`v0.8.1` 起强制，历轮复审清零英文残留）。
- 协议层仅保留必要的英文 token（`[Critical]`，DSML/围栏格式、`tool_calls` 等）——属设计需要，非不一致。
- 中文场景（飞书/微信/CLI/Web）的交互文案连贯，人为注入「皮皮虾/兄弟」人设称呼稳定。

## 4. 处理效率 — 8.8/10

**实测（本会话）：**
- 启动 + 33 工具注册快（毫秒级）；全量 452 项测试约数秒跑完。
- bench（stub LLM 隔离网络）：并发 10/30 轮 p50 ≈ 67ms；长会话连打 30 轮 ≈ 7.6ms/轮，0 失败、0 内存泄漏迹象。
- 多 provider 并发健康探测 + 只对可用者调用，避免串行等 180s 超时。

**可优化点：**
- 单轮对话延迟与 token 成本被**系统 prompt 体量**抬高（见维度 2），压缩辅助调用限时 10s 兜底，但主对话仍受模型与注入量共同约束。
- 军团/DAG 子进程通信为 JSON 行协议，未做批量化，规模大时开销上升；dense 检索每次查询都要对外部 embedder 调用（有内存缓存缓解）。
- 无内置的 batch/多请求并发编排层（除军团外单 agent 串行）。

## 5. 用户体验 — 8.8/10

**流畅处：**
- 双入口：CLI（快捷键、`/proactive` 等）+ HTTP/Web（聊天 + 会话 + 工具 + 设置）。
- Web 四设置页齐全（通用/模型/插件/预设），MCP 配置 + 工具启停 UI + 首启引导。
- 本轮进一步去摩擦：**token 持久化后重启不再失效**、默认会话按天分片不再单文件无限涨、`401` 给出可读引导、网络异常可读化。
- `ppx-channels` 交互式自助配置 + 连通性实测，减少手工碰 config。

**短板：**
- Web 设置页偏基础，缺少可视化「命令守卫/记忆/安全」深度配置表单（多数靠手改 ppx.json）。
- `localIntent` 对打字习惯差的用户偶有误拦截（规则误判），无关闭外的弹性。
- 主动提醒/自我进化等高级能力默认关闭，普通用户未必感知；文档（QUICKSTART/CONFIG）在历轮被重建过，但要跟上新配置键（context_window 等）需持续维护。

## 6. 改进建议（按优先级）

**P1（高价值，性价比最高）**
1. **system prompt 瘦身 / 工具描述按需加载**：当前核心价值+persona+记忆+经验+33 工具描述全量注入，是 4k 本地模型溢出的根因。建议把工具描述改为「先注入工具名清单，仅在选中时注入全量 schema」或用层叠描述；同时提供工具类别的精简层。这比继续在裁剪上修修补补更治本。
2. **本地 provider 窗口自动探测**：`_histTokenCap` 目前对未知窗口回退 8192（→预算 4915），会超过真实的 4096 窗口，首次仍可能溢出、依赖重试。建议：本地 http provider 未见 `context_window` 时按 `model` 常见窗口映射或下调保守默认，减少"先溢出错再重试"的一次往返。

**P2（体验与健壮性）**
3. **记忆语义检索接入易用化**：dense 需外部 embedder，默认纯 BM25。建议文档给出一键配本地 embedding 的引导，或内置一个极轻的孪生/哈希索引缓解"零依赖无语义召回"。
4. **Web 安全/记忆深度设置页**：把命令守卫、记忆衰减、安全策略做成表单，减少手改 ppx.json；顺带在首次启动做 setup 向导收拢 token/模型。
5. **`dispatch`/角色分工 API**：要么补一个内置消费方把它用起来，要么在文档标注"实验性"，避免镀金面误导。

**P3（打磨）**
6. **真实 LLM 回归纳入 CI**：当前 452 测试有 4 个网络跳过、LLM 回归要 secrets。建议加一个「可选 + 有 secrets 才跑」的 E2E 层，防止响应质量回归不被发现。
7. **文档与配置一致性联动**：CONFIG 表 / ConfigStore 的 context_window 等新键已在第十轮接了一致性测试，但 README/QUICKSTART 的初始配置指引要同步，避免"文档没提、用户不知道能调"。
