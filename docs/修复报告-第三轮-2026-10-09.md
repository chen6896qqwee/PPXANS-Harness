## 二、本轮最有价值的三个发现

### 2.1 全量测试耗时从 2 分钟降到 59 秒 —— 因为 headless 审批此前会**空等 120 秒**

`ask` 决策在**没有审批面**的进程里，旧行为是走 `_requestApproval()` 建一个 pending 然后等 `approval_timeout_ms`（默认 **120 000 ms**）超时才算拒绝。

也就是说：CLI 批处理 / 无人值守 / 测试里，任何一次需要审批的工具调用都在**白等两分钟**。本轮把它改成「没有审批入口 → 立即拒绝，并把可自纠的提示一并返回」，测试总耗时直接腰斩。

### 2.2 `apply_patch` 把两种完全不同的情况压成同一个 ask

`apply_patch` 的目标路径藏在 `content` 字符串里，通用 `collectPaths` 看不见 → 一律升级审批。但"升级审批"把两种情况混成一种：

| 情况 | 正确处理 | 旧行为 |
|---|---|---|
| 补丁**确实越界** | 升级审批（一分不放宽） | ask |
| 补丁**没写目标**（用法错误） | 告诉模型三种合法写法，它改一下就能过 | ask（同一句通用文案） |

后者在 headless 里模型既改不了也换不了路，只会幻觉"已修复"收场。

本轮实现**落点证明三态**：`allow`（落点全在根内，免审批直通）/ `escapes`（越界，照旧审批，**不给** modelHint）/ `unprovable`（落点不可确定，给三种写法的可自纠提示）。用 `headless` 场景实测：模型现在收到的拒绝消息里点名了 `path 参数` / `SEARCH 上一行` / `*** Update File:` 三种写法 **+ 复述它实际发出的内容**。

### 2.3 codex 风格补丁此前"解不出又不说明"

模型实测会吐 `*** Begin Patch / *** Update File: 路径 / @@ / -旧行 +新行 / *** End Patch`，而旧实现只认 SEARCH/REPLACE：

- 解析出 0 块 → 权限层证明不了落点 → 升级 ask → headless 拒
- 工具只回一句"未找到任何 SEARCH/REPLACE 块"，模型无从改写

本轮补上 codex 解析（还原成**等价 SEARCH/REPLACE 块**，应用/回滚完全复用既有 SR 主路径），并刻意**不猜两件事**：`Delete File`（删除交给 `delete_file` 工具，避免误删）、`Move to`（移动语义无法用 SR 表达，猜了会改错文件）。实测 8/8 通过，包括"两个 hunk 覆盖两处引用的 rename-symbol 场景真的让基准任务过关"。

## 三、逐项修复清单

### P0 安全（新增能力）

**`findInlineExec`：解释器内联执行硬拦截**
`node -e` / `python -c` / `bash -c` / `powershell -enc` / `npx <pkg>` / `find . -exec` / `git -c pager=…` —— 首词全是合法命令，能绕过前缀白名单。
实测 **9/9 拦、6/6 放**（`node app.js` / `python -m venv` / `bash build.sh` / `git log` / `find . -name` 全部不误伤），需 `security.allow_inline_exec=true` 显式 opt-in。

**`scanToolResult`：工具结果注入扫描**
攻击载荷常用 `\uXXXX` 转义藏在 JSON 里 —— 原文扫不到，模型解码后就读到了。改为解析 JSON 并把**所有字符串叶子**纳入词表。

**`findEscape` 相对穿越漏洞**
原先只判 `isAbsolute`，`../evil.js` 这类相对穿越**完全漏判** —— 越界补丁与根内补丁拿到同样判定，fail-closed 出现缺口。现统一解析为绝对路径再判。

### 顺带修掉的测试自身缺陷

`amem-plugin.test.js` 在 Windows 上用 `new URL(import.meta.url).pathname` 拼路径，Node 会给出 `\C:\Users\...` 这种非法串 → plugins 目录找不到。仓库里只有这一个文件这么写，改用标准 `fileURLToPath`。这是**测试的跨平台 bug**（Linux/macOS 下 `.pathname` 恰好可用），不是实现缺口。
