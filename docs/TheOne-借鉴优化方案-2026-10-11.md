# 皮皮虾 × TheOne 借鉴优化方案 (2026-10-11)

> 来源: 《国产 Agent 又出黑马：能持续干活，还能自我进化》(TheOne / the1os.io)
> 结论先行: 皮皮虾的模块地图与 TheOne 高度同构 (目标看板≈Goal、evolve≈自我进化、audit/verifier≈Verifier、usage-stats≈token 账本),
> 差距主要在**可观测性(摊开给用户看)**与**验证门槛(证据不够不出提案)**两件事上。

## 一、逐条对照: 文章要点 → 皮皮虾现状 → 行动项

| TheOne 特性 | 皮皮虾现状 | 差距 | 行动项 (按优先级) |
|---|---|---|---|
| 执行/验证分离 (干活的不给自己打分) | 已有 `src/audit/verifier.js` + 审批流 | 验证结果未在 UI 集中展示 | 审查报告页增加"验收记录"块: 每次任务完成后列出 测试命令/退出码/耗时 (数据源 `data/audit` + traces) |
| 先复现再修 (回归测试复现失败后才动手) | agent 提示词无此约束 | 未形成机制 | 在 `/plan`/修复类任务提示词中注入规则: 缺陷修复必须先产出可复现测试 (红) 再修 (绿), 审查器检查该证据链 |
| 长期目标 + 预算 + 定期复盘 | 已有 Goal 看板 (`/api/goalboard`) | 无预算字段、无复盘节奏 | Goal 增加 `budget` / `spent` / `nextReviewAt`; lifecycle ticker 到期提醒复盘 |
| 自我进化: 3 条不同来源证据才出提案, 不够门槛的也列出原因 | 已有 `src/evolve/` playbook | 证据簇门槛与"被拒簇"未暴露到 UI | evolve 报告输出 `proposals / rejectedClusters / belowThreshold` 三段, Web UI 增加只读视图 |
| 运行健康页 (24h 成功率/失败数/心跳/Worker 可用) | `/api/stats` + traces 已有数据 | 无聚合视图 | 新增 `/api/health/summary`: 24h 成功率、失败数、最近心跳、工具可用性; hero 状态条接入 |
| token 消耗一目了然 (模型/请求ID/预估 vs 实际) | `data/usage-stats.json` + tokPill | 只有总数, 无按任务拆账 | usage-stats 增加 sessionId 维度; done 事件回传本次任务累计 token + 估算费用 |
| 报告带出处, 冲突并列不拍板 | 有 evidence 模块 (`src/evidence`) | 引用未渲染 | 审查/研究报告尾部的引用列表可点击回源 |
| 技能目录带版本号 + 签名/回滚 | `src/skills` 56+ 技能 | 无版本与回滚 UI | 技能卡显示 version + 内置/自定义标记; 自定义技能写入前留 .bak |

## 二、本次已落地 (v3.4)

1. **图片发送按钮** (Web UI 补齐)
   - `POST /api/upload`: base64 图片存 `<root>/uploads/`, 文件名消毒 + 防覆盖 + 8MB 上限;
   - `GET /uploads/<file>` 静态回显 (防穿越, 服务默认只绑 127.0.0.1);
   - 输入区新增 📷 按钮: 点选 / 粘贴截图 / 拖拽, 三路上传;
   - 图片相对路径拼进消息文本 → 复用既有 `visionUserContent` 自动注入多模态 (零改动 agent 内核);
   - 用户气泡内联缩略图预览, 点击原图。
2. **侧栏「任务」「空间」分组**
   - 任务: 只读 TaskBoard 视图 (todo/running/done/failed 徽标), 点击在时间线展开步骤清单;
   - 空间: 按项目聚合会话 —— 一个空间绑定一个工作区目录 + 一个常驻会话, 点空间=切工作区+回到该项目的会话, 新会话自动归入当前空间 → 同一项目不再散落一堆重复会话。

## 三、下一步建议顺序

1. `/api/health/summary` 运行健康聚合 + hero 展示 (数据现成, 半天工作量, 用户感知最强)
2. usage-stats 按 session 拆账 + done 事件带累计费用 (糊涂账变明白账)
3. evolve 三段式提案视图 (证据门槛可观测)
4. 缺陷修复"先复现再修"提示词约束 + 审查器检查证据链
5. Goal 预算/复盘节奏
