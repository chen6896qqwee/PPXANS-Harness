## 六、未通过项详情（本会话已发现并修复）

### P1-1：`fetch_page` / `http_request`（GET）完全失效

- **现象**：抓取任何网页或发 GET 请求均报 `Request with GET/HEAD method cannot have body.`
- **根因**：`src/tools/advanced.js` 的 `_fetchWithSsrSafe` 用 `body !== undefined` 判定 body，而 `httpRequest` 默认 `body = null`，导致 GET 被塞入 `JSON.stringify(null) = "null"` 作为 body，undici 直接拒绝。
- **复现步骤**：`agent.tools.call("http_request", { url: "https://api.github.com/...", method: "GET" })` → 即报错。
- **影响范围**：`fetch_page` 与 `http_request` 两个网络工具的 GET 路径全部不可用（POST 带 body 侥幸可用）。
- **修复**：抽出 `serializeRequestBody(body)`（`body == null ? undefined : ...`），`_fetchWithSsrSafe` 复用。
- **回归守卫**：`test/fetch-page.test.js` 新增 `serializeRequestBody` 用例（钉死 `null → undefined`）。
- **复验**：修复后 `fetch_page` 抓 GitHub raw 返回 200/2131 字符，`http_request` GET GitHub API 返回 200。

### 观察项（非缺陷，供参考）

1. **`web_search` 外部源在国内不可达**：DuckDuckGo 抓取超时（被墙）。工具已留智谱原生联网回退（`llm.nativeWebSearch`），建议国内场景显式走该回退或换必应/搜狗源。
2. **npm 元数据滞后**：`npmjs.com/package/ppxans-harness` 描述仍为旧版（85 工具/1014 测试），与本地 v3.2.3 不同步，发版时需同步。
