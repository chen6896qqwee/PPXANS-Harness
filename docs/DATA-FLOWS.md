# PPXANS-Harness · 数据流透明披露 (NOTICE)

> 吸收智谱 ZCode 的 NOTICE.md 透明披露模式 (2026-10-02): 把"数据去哪了"从黑盒变成可审计的白盒。
> ZCode 的教训: 静默上传用户代码库与 Git 历史 → 400 人维权 → 整改开源。皮皮虾的立场是**本地优先、显式出站**——
> 本文档按业务场景列全所有出站数据流; 不在表中的出站行为 = 架构缺陷, 欢迎以 issue 形式举报。

**审计方法**: `grep -rn "fetch(\|https://" src/"` 全量扫描出站触点, 本文档与代码同步维护。
**审计日期**: 2026-10-02

## 数据流出站清单

| # | 业务场景 | 触发条件 | 数据范围 | 去向 |
|---|---------|---------|---------|------|
| 1 | 主对话/工具循环 LLM 请求 | 用户发消息且已配置模型 | 用户消息 + 会话历史 + 系统提示 + 工具结果 | 用户自配的模型厂商 (config/ppx.json providers) |
| 2 | 辅助 LLM 请求 (记忆提取/摘要/压缩) | 对话后自动; 仅当配置 `model_routing.aux` | 对话片段摘要 | 用户指定的辅助厂商; **未配置 = 跟随主厂商** |
| 3 | LLM 降级链 | 主厂商失败时自动切换 | 同 #1 | 配置中的下一个厂商 (按顺序) |
| 4 | 网络搜索工具 | agent/用户显式调用 `web_search` | 查询关键词 | DuckDuckGo (html.duckduckgo.com) |
| 5 | 网页抓取工具 | 显式调用 `fetch_page` / `http_request` | 目标 URL 请求 | 用户指定的 URL |
| 6 | 飞书 Bot 通道 | 用户配置飞书渠道后收发消息 | 消息内容 + open_id | open.feishu.cn (用户自己的应用凭据) |
| 7 | MCP 服务端 | 本机客户端连接 | 无出站 (仅监听 127.0.0.1:8899) | 无 |

## 明确不做的事

- ❌ 不上传代码库快照、Git 历史、文件内容到任何官方服务器 (无"快照/工作区同步"机制, 可审计验证)
- ❌ 无遥测/埋点/崩溃上报 (src/ 内无任何统计上报端点)
- ❌ 不在模型请求外夹带任何附加请求 (模型网关转发机制不存在——直连用户配置的厂商)

## 用户自担部分 (ZCode NOTICE 同款声明)

用户自行编写的脚本、配置的任意 MCP 服务、自定义工具 (custom-tools/) 或另行安装的第三方组件,
可能具有额外的数据发送行为——**不能仅因通过皮皮虾启动, 就推定其用途或接收方已经获得官方审核**。

## 本地数据存储

| 数据 | 位置 | 说明 |
|------|------|------|
