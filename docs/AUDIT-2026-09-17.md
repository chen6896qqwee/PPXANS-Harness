## 二、核心运行时

### 2.1 主循环实测行为

`chat()`（`src/agent/index.js:244`）单轮链路：
`clearInterrupt()` → `bus.emit(chat/user)` → `_localIntent()`（本地意图预判，命中则 0–4ms 返回，**不调 LLM**）→ 未命中则 `ctx.consume("modes").run(mode)` → `runToolLoop()` → 落盘会话/记忆 → `_lifecycleTick()` → `evolve.tick()` → 追加降级提示。

`runToolLoop()`（`src/core/policy.js:185`）内置 5 层保护，实测均有真实实现：

| 保护 | 阈值配置项 | 默认 | 位置 |
|---|---|---|---|
| 轮次上限 | `max_tool_rounds` | 8 | `policy.js:203` |
| 上下文溢出降档裁剪 | `OVERFLOW_SHRINK_MAX` | 2 档，下限 200 token | `policy.js:124-131` |
| 工具错误喂回重试 | `max_tool_error_retry` | 2 | `policy.js:163` |
| 探索空转熔断 | `explore_break_limit` | 连续 3 轮 | `policy.js:152` |
| 重复调用告警 | `repeat_flag_limit` | 同签名 2 次 | `policy.js:156` |
| 工具结果裁剪 | `tool_result_budget` | 4000 字符（保头 70%/尾 30%） | `policy.js:49` |

| 级别 | 问题 | 证据 | 影响 |

### 6.2 接口层问题

| 级别 | 问题 | 证据 | 影响 |
|---|---|---|---|
| **P0** | **任意网站可窃取本机 token** | `http.js:493` `/api/bootstrap` 对回环请求免鉴权；`http.js:264` CORS 默认 `*`。**实证**：`curl -H "Origin: https://evil.example.com" http://127.0.0.1:8898/api/bootstrap` → `200` + `ACAO: *` + 响应体含 `"authToken":"015c170b…"` | 用户访问任意恶意网页 → 该页 `fetch` 本地端点读到 token → 拿到 token 后可调全部 API（读写文件、执行命令）。**这是本次体检最严重的问题** |
| **P0** | **`ppx-channels` 入口完全不可用** | `src/channels-cli.js:16` 的 `ensureUTF8Console();` 被误插进第 13 行的 `import {` 语句内部。**实证**：`node bin/ppx-channels.js` → `SyntaxError: Identifier 'ensureUTF8Console' has already been declared` | `package.json` 声明的 5 个 bin 之一彻底失效；通道管理这一整块功能不可达 |
| **P0** | **SSE 并发护栏失效** | `http.js:357` 先 `writeHead(200, SSE头)`，`:363` 才 `_acquire()`；超限时 `_acquire` 内 `writeHead(429)` 抛 `ERR_HTTP_HEADERS_SENT`，被外层 catch 转成 SSE error 事件。**实证**：占满 4 槽后第 5 个请求收到 `HTTP 200` + `Content-Type: text/event-stream` + 正文 `data: {"type":"error","error":"Cannot write headers after they are sent to the client"}`（**Node 内部错误原文直接泄漏给客户端**） | 超限用户看到"空回复 + 永久转圈"，而非 429 提示；同时泄漏服务端实现细节 |
| **P1** | **SSE 首包不 flush** | 同上快照：`writeHead(200)` 后无任何 `res.write` 或 `res.flushHeaders()`。**实证**：4 个已获槽位的请求 **6 秒内收不到任何响应头** | LLM 慢首包时前端完全无反馈；经反向代理/网关极易被判超时断开；无法做 SSE 心跳 |
| **P1** | **token 比较非恒定时间** | `http.js:218` `return h === "Bearer " + this.authToken` | 理论计时侧信道；绑 `0.0.0.0` 场景下应修 |
| **P1** | **前端与 `legacy_rest` 开关不兼容** | `public/app.js` 实调 `/api/settings`、`/api/providers`、`/api/traces`、`/api/stats`、`/api/memory`、`/api/lifecycle`、`/api/proactive`、`/api/workspace/*`；`http.js:487` 一旦 `legacy_rest=false` 全部返回 410 | 用户按文档把 REST 退役后，**设置页/模型页/抽屉面板/工作区树整体失效**，只剩对话可用 |
| **P1** | **无全局异常兜底** | 全项目 `grep` 只有 SIGINT/SIGTERM 处理，**无 `uncaughtException` / `unhandledRejection`** | Node ≥15 下未处理拒绝即进程崩溃；一次工具异常可能让整个服务消失，用户只看到"未连接" |
| **P1** | 限流令牌桶永不回收 | `http.js:65` `_buckets = new Map()`，`:225-229` 每个新 IP 建桶，无清理 | 长期运行 + 多变源地址 → 内存缓慢增长 |

| **P2** | 无请求超时保护 | 未设 `server.headersTimeout` / `requestTimeout` | 慢速请求可缓慢占用连接 |
| **P2** | 无 CSP 头 | `/` 响应只有 `Content-Type` + `Cache-Control` | 缺失 XSS 兜底防线（与 UX-P1-1 叠加） |
